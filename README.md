# 📻 Fragment

**A 3–4 player puzzle where an old radio listens to everything you say.**

Each player holds one fragment of the radio's code: the *signs*, their *order*, the *tones* of the keys, or the
*rule* that distorts it. Nobody can open it alone. You can only talk through the chat, and the radio reads every
message. Say a plain word ("red", "triangle", "first") and it turns to static. So you speak in metaphors…
and the radio **learns** them.

When you open it, your team receives a **Fragment**: a record of the language you invented together, generated by the server. Solana NFT minting is planned.

> Built for the **iDos Games × Solana** track of the Colosseum hackathon. Status: **beta**.

---

## Trials

A game is **five trials**, selected randomly without repetition from **twenty** rules.
Picture sets and private clues are regenerated for each match. Every player owns
one control and must confirm their own answer. The shared rule is visible to all;
private clues belong to neighbours or are distributed across the team's hands.

See [the complete trial catalogue](TRIALS.md). The pool contains four original
trials, four new card-comparison trials, six numeric ciphers and six picture-scale
ciphers. The latter reuse the controls but change how clues become answers.
`npm run check` verifies unique solutions and distributed information for every
rule with three and four players.

Players speak **in turns** (3 messages or 30 seconds), and the camera follows whoever holds the floor.

## How a round works

1. 3–4 players join a room with a 4-letter code.
2. The server hands out the fragments. Each player only ever receives their own piece.
3. Players talk in the chat. The **Listener** checks every message:
   - plain words (tones, signs, numbers, order words, in English and Russian) become `▓▓▓` static and raise the radio's suspicion;
   - words the team keeps repeating get **learned**: after that, they become static too;
   - only the speaker is told which words were overheard.
4. The radio's *magic eye* opens as its suspicion grows. At 100% it **retunes**: a brand new code, every fragment is useless.
5. Three attempts per trial, ten minutes for the whole match. Pass all five trials to open the radio.

## Design rule: off-chain play, on-chain memory

Gameplay is fully off-chain (WebSocket, authoritative server). Current and planned integrations:

| | Status |
| --- | --- |
| Wallet identity (Phantom / Solflare / Backpack) | ✅ signed wallet binding and profile recovery; verified addresses attached to players and the Fragment |
| Fragment record: players, invented lexicon, cracked words, time, overheard, retunes, wrong codes | ✅ beta: generated by the server on a verified win |
| Fragment minted on Solana (Metaplex Core, server-authorized) to every participant | ⏳ next build |
| The radio learns from **all** published Fragments: metaphors sealed on-chain are known to it in future games | ⏳ planned |
| iDos Games: accounts, leaderboard, LLM judge via AI Services | ⏳ planned |

## Run locally

Online matchmaking and friend rooms require a profile linked to a Solana
wallet through a verified message signature. Creating, joining and resuming
online rooms are checked by the server. Practice with bots remains open to
guests. Merely sending a wallet address does not grant online access.
Current cosmetics and Signal are off-chain game data; NFT minting is planned.

### Signal and cosmetics

The shop offers three cosmetic skins (20, 60 and 120 Signal), plus the free
default character. Wins award 10 Signal in practice or 25 with humans. A player
must send at least two messages; human matches must last at least one minute.
The earning cap is 100 per account per UTC day. Rewards are deduplicated by
round and account. Purchases and ownership are checked on the server; equipping
a skin broadcasts the character's appearance to the whole room.

Profiles are persisted in `.data/profiles.json` (override `FRAGMENT_DATA_DIR`).
The shop is available only in the main menu. A separate **Sign in with wallet**
button links or restores your profile.
The browser keeps a device access token. Link a wallet by signing
an expiring message (no transaction). The wallet restores the same profile on
another device or after clearing browser data. If it belongs to an existing
profile, confirm switching; guest balances and items are never merged.
Unlinked guest profiles cannot be recovered after losing their device token.
For HTTPS hosting, set `FRAGMENT_PUBLIC_ORIGIN` to the exact public origin
(for example `https://game.example.com`), without a trailing slash.
This prototype has no transferable token or NFT minting.
It is not a Sybil-resistant reward economy: multiple device accounts remain
possible. Keep the data directory private and persistent when hosting.

### Finding teammates

**Find a random match** gathers real players in public waiting rooms, separate
from private friend rooms and solo practice. Once three players join, an
eight-second countdown allows a fourth to join before the game starts
automatically. Leaving below three cancels the countdown. **Cancel search**
returns to the menu. Matchmaking currently runs within one server process;
players need access to the same hosted server to meet online.

### Sound and display

The Settings button is available on every screen. Audio includes an original
procedural ambient drone, radio hiss, and action cues. Music tension follows the
radio's suspicion. Master, music, ambience, and effect volumes can be adjusted
independently; audio begins after a click or key press and pauses in hidden tabs
by default. Settings also include Russian/English, camera movement, reduced
motion, film grain, and static flashes, saved locally on the device. The settings
menu does not pause multiplayer rounds.

### Playing solo

Choose **Play with bots** from the main menu. A private practice room includes two
server-managed companions, Echo and Wren, in both development and production.
Start with **Turn the radio on**; no wallet is required. Bots explain clues in the
selected interface language and use preset correct answers after the human writes
a message. They do not interpret the human's hints. Practice keeps the same five randomly selected
trials, ten-minute limit, suspicion, and turn rules. In the lobby, **Main menu**
lets you switch between practice and playing with friends.

Requires Node.js 18+.

```bash
npm install
npm run dev          # server on :2567, client on http://localhost:5174
```

Open the client, create a room, and share the code. Testing alone? Fill the room with bots:

```bash
npm run bots -- ABCD 2     # 2 chatty bots join room ABCD
npm run e2e                # end-to-end check of a full round against the running server
```

`FRAGMENT_DEBUG=1 npm run dev` prints each room's solution to the server console (local testing only).

Production: `npm run build && npm start` serves the built client and the WebSocket server on `$PORT`.

## Project structure

```
shared/protocol.ts     messages, types and constants shared by server and client
server/index.ts        HTTP + WebSocket server, rooms registry
server/room.ts         room lifecycle, chat, suspicion, retune, win/lose, Fragment record
server/puzzle.ts       lock generation (unique solution by construction) and role assignment
server/listener.ts     the radio's ears: plain-word detection, stemming, learning
client/src/main.ts     screens: home, lobby, game, Fragment card
client/src/radio.ts    the radio (SVG) and its magic-eye suspicion meter
client/src/glyphs.ts   the 8 signs and 4 tones
client/src/audio.ts    procedural static, thuds and chimes
scripts/bots.ts        test bots
scripts/e2e.ts         end-to-end test
```
