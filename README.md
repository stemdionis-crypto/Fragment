# 📻 Fragment

**A four-player puzzle where an old radio listens to everything you say.**

Each player holds one fragment of the radio's code: the *signs*, their *order*, the *tones* of the keys, or the
*rule* that distorts it. Nobody can open it alone. You can only talk through the chat, and the radio reads every
message. Say a plain word ("red", "triangle", "first") and it turns to static. So you speak in metaphors…
and the radio **learns** them.

When you open it, your team receives a **Fragment**: a record of the language you invented together, generated by the server. Solana NFT minting is planned.

## Trials

A game is **five progressively harder trials** drawn from a catalogue of **fifteen** rules.
The first is always the direct clue exchange. Each later chapter draws one of its rules.
Six picture sets and private clues are regenerated for each match; all five
trials use distinct sets, including weather and radio-station equipment. Every player owns
one control and must confirm their own answer. The shared rule is visible to all;
private clues belong to neighbours or are distributed across the team's hands.

See [the complete trial catalogue](TRIALS.md). The pool contains four original
trials, four card-comparison trials, one numeric cipher and six picture-scale
ciphers. The latter reuse the controls but change how clues become answers.
`npm run check` verifies unique solutions and distributed information for every
rule with three and four players.

Players speak **in turns** (up to 3 messages, with no per-turn countdown), and the camera follows whoever holds the floor. A player can pass early; the ten-minute match limit still applies.

## How a round works

1. Four players join a room with a 4-letter code. In a private room, two friends can fill empty seats with bots.
2. The server hands out the fragments. Each player only ever receives their own piece.
3. Players talk in the chat. The **Listener** checks every message:
   - plain words (tones, signs, numbers, order words, in English and Russian) become `▓▓▓` static and raise the radio's suspicion;
   - words the team keeps repeating get **learned**: after that, they become static too;
   - only the speaker is told which words were overheard.
4. The radio's *magic eye* opens as its suspicion grows. At 100% it **retunes**: a brand new code, every fragment is useless.
5. Three attempts per trial, ten minutes for the whole match. Pass all five trials to open the radio.

## Run locally

Online matchmaking and friend-room access are checked by the server. Standalone profiles bind a Solana wallet through a verified message signature; iDos users sign in through the platform and their sessions are verified server-side. Practice with bots remains open to guests. Merely sending a wallet address does not grant online access.
Current cosmetics and Signal are off-chain game data; NFT minting is planned.

### Signals and cosmetics

The shop offers three paid character skins (1,000 / 1,500 / 2,500 Signals), plus the free default character. Accessories and room items start at 300 Signals.

An eligible human match must last at least 60 seconds and include at least two distinct connected human accounts with at least two messages each. Rewards are 10 Signals for a win or 3 for a qualifying loss, capped at 50 per account per UTC day and deduplicated by account and round. Matches with bots earn zero. These checks limit basic farming but do not prove that two accounts belong to different people.

On iDos, balance and item ownership come from platform inventory. The Store handles purchases; CloudCode validates equipment and reward claims. Equipped cosmetics are broadcast to other players. FRAG packages currently offer 500 / 1,000 / 2,000 / 4,000 SI for 125,000 / 250,000 / 500,000 / 1,000,000 FRAG respectively. Prices are read from the live storefront, not treated as a market exchange rate.

Standalone profiles and server-side match/reward state are persisted in `.data/profiles.json` (override `FRAGMENT_DATA_DIR`). iDos inventory and protected profile/loadout data are stored through the platform.
The profile menu now shows completed matches, wins, fastest multiplayer win,
lifetime Signals earned, balance and owned cosmetics. A wallet-linked leaderboard
has separate speed, lifetime Signals and matches tabs. New players see a short
walkthrough in the lobby and contextual hints during their first three matches.
The free Render backend still uses temporary local storage: pending reward receipts, local wallet-linked profiles and rate-limit state can be lost after a restart. iDos purchases and saved platform equipment use platform storage. Durable backend storage is required before treating reward accounting and hosted rankings as production-ready.
The shop is available only in the main menu. A separate **Sign in with wallet**
button links or restores your profile.
The browser keeps a device access token. Link a wallet by signing
an expiring message (no transaction). The wallet restores the same profile on
another device or after clearing browser data. If it belongs to an existing
profile, confirm switching; guest balances and items are never merged.
Unlinked guest profiles cannot be recovered after losing their device token.
For HTTPS hosting, set `FRAGMENT_PUBLIC_ORIGIN` to the exact public origin
(for example `https://game.example.com`), without a trailing slash.
FRAG has been issued through iDos; this game does not yet mint NFT cosmetics or victory records.
It is not a Sybil-resistant reward economy: multiple device accounts remain
possible. Keep the data directory private and persistent when hosting.

### Cosmetic collection

The main-menu shop has four tabs with previews: characters, accessories, room
and victory effects. Existing skins retain their IDs and ownership but
now use distinct illustrated models based on the character reference: a goblin
with a gas mask, a gamer with a headset, and a hooded masked figure. Accessories use independent headwear and face slots.

Room cosmetics cover the table, wallpaper, lighting, poster and one desk decoration.
Every participant sees the creator's equipped room set. Character accessories are
individual. Victory effects are individual decorations on the victory screen.
Purchases, balances and equipment are validated through the authoritative server and iDos services. Platform accounts use iDos inventory and CloudCode; standalone profiles use server storage.
Old profiles automatically receive free defaults without losing existing skins.

Five purchasable face masks replace the skin's built-in mask rather than layering
over it. Choosing **Original skin face** restores the goblin's gas mask or the
hooded character's original face. Only one face item is equipped at a time.
Emotes have been removed from the game and shop; paid emotes in older profiles
are refunded once during migration. Reduced motion disables victory animations.

These items are currently off-chain cosmetics purchased with Signals, not minted
NFTs. The free hosted demo can reset its temporary profile data after a restart.

### Finding teammates

**Find a random match** gathers real players in public waiting rooms, separate
from private friend rooms and solo practice. Once two players join, a
twelve-second countdown lets more people join; bots fill empty seats before
the four-player game starts. Leaving below two cancels the countdown. **Cancel search**
returns to the menu. Matchmaking currently runs within one server process;
players need access to the same hosted server to meet online.

In a private code room, the host can add bots after a second human joins, remove
them in the lobby, and start once all four seats are filled. A friend who joins
an already full lobby replaces a bot automatically. Solo practice uses one human
and three bots; training matches award no Signals to any participant.

### Sound and display

The Settings button is available on every screen. Audio includes an original
procedural ambient drone, radio hiss, and action cues for the dial, chat,
confirmation, passing a turn and the final minute. Music tension follows the
radio's suspicion. Master, music, ambience, and effect volumes can be adjusted
independently; audio begins after a click or key press and pauses in hidden tabs
by default. Settings also include Russian/English, camera movement, reduced
motion, film grain, and static flashes, saved locally on the device. The settings
menu does not pause multiplayer rounds.

### Playing solo

Choose **Play with bots** from the main menu. A private practice room fills the remaining three seats with server-managed bots.
Start with **Turn the radio on**; no wallet is required. Bots explain clues in the
selected interface language and use preset correct answers after the human writes
a message. They do not interpret the human's hints. Practice keeps the same five randomly selected
trials, ten-minute limit, suspicion, and turn rules. In the lobby, **Main menu**
lets you switch between practice and playing with friends.

Use Node.js 22 for development and deployment.

```bash
npm ci
npm run dev          # server on :2567, client on http://localhost:5174
```

Open the client, create a room, and share the code. Testing alone? Fill the room with bots:

```bash
npm run bots -- ABCD 2     # 2 chatty bots join room ABCD
npm run e2e                # end-to-end check of a full round against the running server
```

`FRAGMENT_DEBUG=1 npm run dev` prints each room's solution to the server console (local testing only).

Production: `npm run build && npm start` serves the built client and the WebSocket server on `$PORT`.

## iDos release workflow

`npm run release:idos` typechecks and builds the actual static game, producing a ZIP in `releases/`. Upload that ZIP with iDos MCP; do not publish an iframe wrapper or rely on the AI editor's starter project. Backend changes must be deployed separately to Render.

See [release instructions](idos/UPDATES.md), [deployment configuration](DEPLOYMENT.md), and [current Signals/FRAG economy](idos/SIGNALS.md). The older FRAG activation section in `idos/README.md` describes a superseded draft.

Useful checks:

```bash
npm run typecheck
npm run check
npm run check:idos
npm run build
```
