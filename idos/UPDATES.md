# Обновление Fragment без платной сборки Engine

Исходники: этот репозиторий. Проект iDos: `49HLIN0J`.
Сервер: `https://fragment-demo.onrender.com`.

1. Внести изменения в исходники. Если изменён сервер, сначала проверить его и обновить сервис Render из соответствующего коммита GitHub; дождаться Live.
2. Выполнить `npm run release:idos` в корне проекта. После свежего клонирования сначала выполнить `npm ci`.
3. Команда проверит TypeScript, соберёт игру локально и создаст ZIP в `releases/`. `releases/latest.json` содержит путь и контрольную сумму последнего архива.
4. Подключить iDos MCP аккаунтом владельца с доступом к Fragment и правом `build:write`. Проверить проект через `list_my_titles`.
5. Вызвать `begin_build_upload({title_id:"49HLIN0J"})`. Загрузить готовый ZIP обычным HTTP PUT на возвращённый `upload_url` (например, `curl.exe --fail --upload-file <ZIP> <upload_url>`). Ссылку загрузки не сохранять в репозитории.
6. Вызвать `finish_build_upload` с тем же TitleID и полученным build_id. Для тестовой версии использовать `deploy:false`, для явно запрошенной публикации — `deploy:true`.
7. Проверить `get_build`, дождаться готовой версии и открыть возвращённый адрес. Проверить вход, профиль, кошелёк и отправку чата в свой ход.

`index.html` лежит в корне ZIP, пути ресурсов относительные. Это сама игра, а не iframe другого сайта. WebSocket подключается к Render.

Этот способ не запускает платную сборку или генерацию iDos и не расходует AI-кредиты. Архив и файлы используют уже доступную квоту хранилища. При ошибке квоты остановиться; не покупать тариф автоматически.

При `TITLE_NOT_ALLOWED` переподключить MCP и выбрать Fragment в разрешениях. Вход в браузере сам по себе не выдаёт доступ MCP. Не публиковать старую Dev-сборку вместо нового ZIP.

Пример запроса помощнику: «Собери текущую версию командой release:idos и загрузи ZIP в Fragment через MCP без платной сборки. Проверь тестовую ссылку и опубликуй обновление».
